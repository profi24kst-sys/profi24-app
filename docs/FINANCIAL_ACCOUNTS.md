# Денежные счета и аудируемый журнал

Финансовый модуль CRM хранит движение денег как неизменяемый журнал. Остаток счёта не является редактируемым полем: он рассчитывается как сумма приходов минус сумма расходов.

## Возможности первого релиза

- денежные счета типов `BANK` (расчётный счёт), `CARD` (корпоративная карта), `CASH` (наличная касса), `ADVANCE` (подотчёт) и `OTHER`;
- ответственный сотрудник, комментарий и активность счёта;
- начальный остаток только отдельной операцией `OPENING` с основанием;
- расходы, приходы, оплаты клиентов, возвраты, покупки запчастей, корректировки и сторно;
- перевод между счетами как две связанные операции одинаковой суммы;
- привязка операции к заказу, сотруднику, документу и записи истории;
- повтор запроса с тем же `Idempotency-Key` безопасен, а повтор с другими данными отклоняется.

В журнале используются пять бизнес-сущностей: `finance_accounts`, `finance_transactions`, `finance_transfers`, `finance_categories` и `finance_audit_log`. Техническая таблица `finance_schema_migrations` хранит применённые версии миграций.

## Права

OWNER создаёт и редактирует счета, выполняет переводы и корректировки и видит весь журнал. Менеджер и инженер видят только активные счета, назначенные им, и могут выбрать такой счёт при операции по доступному заказу. Прямое редактирование остатка, удаление операции и удаление платежа запрещены для всех ролей.

Для исправления используется новая операция сторно с причиной. Возврат оплаты оформляется отдельной операцией возврата, которая сохраняет исходный платёж и уменьшает задолженность клиента.

## Покупка запчасти

Действие «Купил запчасть» требует счёт, закупочную цену, количество и чек/документ. Запчасть и списание создаются в одной транзакции. Уже оплаченная покупка не переписывается и не удаляется.

## Перенос со старой базы

Миграция `001-auditable-accounts.sql` переносит исторические начальные остатки, платежи, возвраты и старые операции в журнал. Старые способы оплаты сопоставляются с типом счёта только для исторических записей. Нераспределённые старые записи попадают в неактивный счёт «Не распределено: старые операции» для проверки OWNER. Новые операции без явного счёта отклоняются.

Перед обновлением рабочей базы сделайте обычный дамп. Миграция не удаляет старые записи, но после её применения записи денег становятся неизменяемыми по правилам модуля.

## Проверки перед выпуском

В каталоге `server` доступны:

```bash
npm run check
npm run test:finance
```

Тесты проверяют сценарий 300 000 + 120 000 − 48 500 − 2 250 − 50 000 = 319 250 ₸, отдельный счёт подотчёта 50 000 ₸, переводы без влияния на P&L, права ролей, идемпотентность и запрет переписывания журнала.

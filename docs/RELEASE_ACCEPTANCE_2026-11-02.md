# PROFI24KST — единая версия для приёмки, 02.11.2026

Ветка: `release/crm-acceptance-20261102`. База выпуска: `main` на `2121a4ee0c994dcbc0a2549453748b1a2d3c3daf`.
Включены последние изменения PR #112–#117 и приведённые ниже исправления. Эта версия готовится для технической и пользовательской приёмки; её наличие не означает внедрение в рабочую CRM или закрытие всего ТЗ.

## Что собрано и исправлено

- Личные представления, колонки, фильтры и быстрые списки заказов; обновлённая карточка, одна форма приёма.
- Атомарное создание клиента/техники/заказа и истории; повтор с прежним ключом; восстановление черновика, защита от устаревшей вкладки.
- Статьи ДДС, методы оплаты и отчёт за период.
- Экспорт из «Отчётов» использует выбранный диапазон дат. Заказы отбираются по дате создания в Костанае, клиенты — по связанным заказам этого периода; расчёт сумм и права филиалов не расширяются. Это выгрузка заказов/клиентов, а не полный экспорт финансовых проводок.
- Закрытие кассовой смены с расхождением требует комментария. Проверка есть в интерфейсе, API и новой миграции `010-cash-shift-variance-note`. Исторические смены и суммы не переписываются; документирование разницы не создаёт искусственную корректировку кассы.
- Сквозной тест шести ролей теперь начинается с нового атомарного приёма. Проверяет повтор, назначение, наставника/стажёра, фото, диагностику, согласование, склад, тестирование, запрет недопустимых оплат, повтор оплаты, подпись, закрытие, гарантию, документы и сверку кассы.
- Браузерный пилот проверяет создание менеджером, принятие инженером через список, запрет оплаты инженеру и видимость комментария/статуса у менеджера после перезагрузки.
- Неизменяемость версий документов включена в обязательный `test:crm`, а не только в отдельный тестовый файл.

## Проверки кандидата

Обязательные: весь `test:finance`, `test:orders`, `test:crm`, сборка web, полный Docker graph, PostgreSQL recovery, UI Browser Acceptance, audit/security/load workflows. Зелёные результаты должны относиться к точному HEAD общего PR; результаты от 5 октября не являются проверкой этой версии.

Новые/расширенные проверки:

- `server/test/staff-day-acceptance.test.js` — шесть ролей, новая приёмка, склад/касса/закрытие и документированное расхождение.
- `server/test/directory-routes.test.js` — обе границы локальных дат, JSON/XLSX, клиенты, чужой филиал, отзыв прав, ошибочные периоды.
- `server/test/document-versioning.test.js` — неизменяемые версии документов, включён в обязательный набор.
- `web/e2e/staff-pilot-browser.cjs` — принятие инженером и передача результата менеджеру.
- `web/e2e/report-exports-period.cjs` — два реальных скачивания, даты отчёта, блокировка неверного диапазона.

## Порядок доведения до запуска

1. Принять общий кандидат после полного CI; проверить локальную копию по инструкции ниже.
2. Закрыть оставшиеся требования безопасности SEC-2/3, прайс ENG-1 и финансовый экспорт/акт FIN-2/4. Не выдавать зелёный CI за выполнение этих бизнес-требований.
3. Довести роли/онбординг, справочники, B2B и клиентские каналы. Для приёмки нужны согласованные реквизиты/контакты и тестовые получатели.
4. Отдельно завершить розницу/запчасти, оффлайн и миграцию HelloClient, сохраняя требования единого ТЗ.
5. Выполнить `PILOT_ROLLOUT_CHECKLIST.md` на согласованном стенде, затем согласовать перенос в рабочую среду. Реальные деньги, исходные остатки и массовый импорт не изменяются автоматически.

## Обновление существующего локального тестового стенда

Для каталога пользователя `C:\Users\Пользователь\profi24-app`, существующего `.env.local` и отдельного Compose project `profi24-local`. Сначала сохранить собственные изменения обычным commit. Не пересоздавать настройки или тома. При ошибке каждой команды остановиться.

```powershell
cd "C:\Users\Пользователь\profi24-app"
git fetch origin
git switch release/crm-acceptance-20261102
git pull --ff-only origin release/crm-acceptance-20261102
docker compose -p profi24-local --env-file .env.local up -d --build
docker compose -p profi24-local --env-file .env.local ps
```

Миграции выполняются новым api при запуске. Проверить `http://localhost:5173`, приём/восстановление черновика и период экспорта. Кассовые проверки делать исключительно на искусственных данных этого тестового проекта. Production-процедура описана отдельно в `PRODUCTION_RUNBOOK.md`.

# Приём заказа в одной форме

Кнопка «Новый заказ» открывает форму с выбором сценария в начале. Клиент, техника и обращение видны вместе, без кнопок «Далее». На телефоне блоки располагаются вертикально; действия сохранения остаются внизу панели.

Существующие клиенты ищутся по имени/телефону, техника загружается только для выбранного клиента. Смена клиента сбрасывает выбор техники. Выездной ремонт и платный стационар сохраняют прежнюю серверную привязку типа посещения. Дополнительные поля загружаются из конструктора для выбранного сценария; смена сценария очищает несовместимые значения. Серверная валидация обязательных полей остаётся действующей (FLEX-1/FLEX-3 единого ТЗ от 27.09.2026).

Ошибки показаны рядом с полями; фокус переходит к первой ошибке. Поиск, загрузку техники и схему полей можно повторить. Пока схема или техника не загружены, отправка недоступна. При отправке поля, закрытие и Escape блокируются. Подтверждённые сервером ID нового клиента и техники повторно используются после отклонения заказа, если данные этих записей не изменились. После успешного создания форма закрывается до обновления списка.

Это не серверная идемпотентность: если соединение пропало после записи, но до получения ответа, результат операции остаётся неизвестным. Объединение отдельных API создания клиента/техники/заказа в транзакцию и защита от повторов при неизвестном результате — отдельная задача. Черновик приёма между закрытиями формы также пока не сохраняется.

Проверки: синтетический `order-intake-workspace.cjs` (ошибки/повторная загрузка, обязательные поля, повторное использование подтверждённых ID, двойной клик, Escape при отправке, существующий клиент/техника, FIELD/PAID_WORKSHOP и ширина 390 px); обновлённые живые сценарии CI валидации, поиска, конструктора, типов заказа и пилота ролей выполняются в изолированном стенде. Реальные данные клиентов не используются.

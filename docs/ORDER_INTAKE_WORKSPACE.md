# Приём заказа в одной форме

Кнопка «Новый заказ» открывает форму с выбором сценария в начале. Клиент, техника и обращение видны вместе, без кнопок «Далее». На телефоне блоки располагаются вертикально; действия сохранения остаются внизу панели.

Существующие клиенты ищутся по имени/телефону, техника загружается только для выбранного клиента. Смена клиента сбрасывает выбор техники. Выездной ремонт и платный стационар сохраняют прежнюю серверную привязку типа посещения. Дополнительные поля загружаются из конструктора для выбранного сценария; смена сценария очищает несовместимые значения. Серверная валидация обязательных полей остаётся действующей (FLEX-1/FLEX-3 единого ТЗ от 27.09.2026).

Ошибки показаны рядом с полями; фокус переходит к первой ошибке. Поиск, загрузку техники и схему полей можно повторить. Пока схема или техника не загружены, первая отправка недоступна. При отправке поля, закрытие и Escape блокируются. После успешного создания форма закрывается до обновления списка.

## Надёжное сохранение и черновик

Форма использует `POST /api/v1/requests/intake` с UUID v4 в `X-Idempotency-Key`. Клиент, техника, заказ, история создания/назначения и запись ключа создаются в одной транзакции. Ошибка откатывает все новые записи. Повторные и одновременные запросы с тем же ключом и точными данными возвращают тот же заказ (201 при создании, 200 при повторе). Другие данные под использованным ключом отклоняются с 409. Ключ принадлежит сотруднику; повтор проверяет текущий доступ к заказу и филиалу. Инженер должен быть активным инженером филиала; существующая техника должна принадлежать выбранному клиенту и быть доступна сотруднику. Сообщение о дублирующемся телефоне не раскрывает данные чужого филиала.

Черновик хранится в браузере отдельно для сотрудника и его роли. Закрытие, перезагрузка и повторный вход восстанавливают поля; обычный черновик можно очистить. Обычные черновики истекают через 7 дней. Перед первым запросом сохраняются ключ и точное тело операции. Пока результат не подтверждён, поля зафиксированы, а кнопка «Повторить сохранение» использует прежнюю операцию даже после перезагрузки и выхода/входа. Такая операция не истекает автоматически и не очищается вручную через форму: потеря ключа могла бы создать дубль. После подтверждения сервером черновик удаляется. Если сервер подтвердил откат ошибкой с `safe_to_edit`, форму можно исправить и отправить заново. Если браузер не может сохранить ключ, запрос не отправляется.

Выход удаляет учётные данные и остальные прежние локальные данные, сохраняя только привязанные к сотруднику черновики приёма. Они не доступны через форму другого сотрудника/роли. Черновик содержит имя, телефон, адрес и введённые поля; используйте доверенный браузер. Удаление данных браузера или повторное создание в другом браузере теряет локальный ключ; перед новым заказом проверьте список. Старые отдельные API `/customers`, `/equipment`, `/requests` остаются совместимыми и не приобретают эту гарантию: она применяется к новому приёму с одним ключом операции.

## Проверки

- `server/test/order-intake.test.js`: повтор/одновременные вызовы, изменение данных под ключом, откат при сбое истории без оставшихся клиента/техники, сценарии и дополнительные поля, инженер, принадлежность техники/филиалу, скрытие чужого клиента, текущие права и блокировка учётной записи.
- `web/e2e/intake-draft-store.test.js`: сохранение/изоляция, срок хранения, сохранение неизвестной операции, повреждённый ключ, отказ хранилища, выход без потери операции.
- `order-intake-workspace.cjs`: синтетическая проверка ошибок/повторов, двойного клика, Escape, существующих записей, FIELD/PAID_WORKSHOP и ширины 390 px.
- `order-intake-recovery.cjs`: живой изолированный CI-стенд, черновик после закрытия/перезагрузки, потеря ответа после серверного commit, выход/вход и повтор с тем же ключом/данными, отсутствие дублей клиента/техники/истории, одновременные запросы на PostgreSQL, блокировка отправки при отказе localStorage.

Обновление локального тестового стенда требует пересборки **api и web**; серверные миграции применяются при запуске. Используйте существующие `.env.local` и Compose project `profi24-local` из `LOCAL_WINDOWS_TEST.md`; не пересоздавайте пароли и тома. Эта ветка включает зависимые изменения PR 112–116. Реальные данные клиентов при разработке и проверках не используются.

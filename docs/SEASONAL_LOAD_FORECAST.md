# F28 — сезонный прогноз загрузки

Раздел находится в «Аналитике директора» и отвечает на три вопроса: сколько заявок ожидается, хватит ли мощности по каждой категории техники и насколько прогнозу можно доверять.

## Данные и горизонт

- спрос считается по созданным, не удалённым и не отменённым заявкам;
- текущий неполный месяц не используется как завершённый факт;
- стандартная история — 24 полных месяца, допустимо 12–36;
- стандартный горизонт — 3 месяца, допустимо 1–12;
- расчёт разделён по филиалу и категории техники.

## Модель

Прогноз каждого месяца = 65% факта того же месяца прошлого года + 35% среднего за последние три полных месяца. Если годовой истории ещё нет, используется среднее последних трёх месяцев.

Это намеренно объяснимая модель: директор видит, откуда взялась цифра, а результат можно проверить на данных CRM.

## Проверка ошибки

Для каждой специализации и для всей компании выполняется backtest на последних шести полных месяцах. API возвращает:

- `MAE` — среднее абсолютное отклонение в заявках;
- `WAPE` — суммарную ошибку относительно фактического объёма;
- `accuracy_pct` — `max(0, 100 − WAPE)`;
- количество точек, на которых измерена ошибка.

Уровень доверия `HIGH / MEDIUM / LOW` зависит от глубины истории, объёма данных и фактической ошибки. `LOW` нельзя использовать как единственное основание для найма.

## Мощность инженеров

Плановая мощность активного инженера — 22 рабочих дня × 6 заказов в день. Она распределяется между филиалами и категориями пропорционально закрытым этим инженером заказам за последние 12 месяцев. Поэтому один мастер не учитывается с полной мощностью сразу в нескольких специализациях.

Инженеры без закрытых заказов за расчётный период показаны отдельно как «не классифицировано мастеров» и не создают ложную специализированную мощность.

## API

`GET /analytics-api/v1/seasonal-load-forecast`

Параметры: `as_of`, `history_months`, `horizon_months`, опционально `branch_id`. Доступ наследует право `analytics.view`; филиальная область проверяется на сервере.

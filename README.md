# PROFI24KST CRM

Эксплуатационный MVP CRM для сервисного центра PROFI24KST.

## Реализовано

- авторизация и роли Owner / Manager / Engineer;
- клиенты с защитой от дублей по телефону;
- карточки оборудования и история ремонтов;
- заявки с уникальной нумерацией, источником, приоритетом и SLA;
- назначение и принятие заявки инженером;
- контролируемые статусы заявки;
- диагностика;
- согласованные работы и версии согласований;
- прямые затраты, валовая прибыль и маржа заявки;
- оплаты, частичная оплата и возврат денежных средств;
- запчасти и жизненный цикл детали;
- автоматическая задача менеджеру после поступления детали;
- задачи сотрудников;
- рекламации и классификация G1–G8;
- Quality Incident для ошибок диагностики/ремонта;
- dashboard управляющего/собственника;
- финансовый dashboard месяца;
- история действий заявки;
- rate limiting, security headers и JWT;
- PostgreSQL migrations для новой и существующей базы;
- Docker Compose;
- health checks;
- адаптивный интерфейс для телефона;
- CI workflow;
- резервное копирование и восстановление PostgreSQL.

## Быстрый запуск

```bash
cp .env.example .env
```

Обязательно поменяйте в `.env`:

- `POSTGRES_PASSWORD`;
- `JWT_SECRET`.

Запуск:

```bash
docker compose up -d --build
```

Открыть:

```text
http://localhost:5173
```

Проверка состояния:

```text
http://localhost:5173/health
```

## Первичный вход

Для первого запуска создаются тестовые учётные записи:

- `owner@profi24.kz` / `profi24`
- `manager@profi24.kz` / `profi24`
- `engineer@profi24.kz` / `profi24`

### Критично для эксплуатации

Сразу после первого запуска смените пароль директора:

```bash
docker compose exec api npm run set-password -- owner@profi24.kz 'НОВЫЙ-СЛОЖНЫЙ-ПАРОЛЬ'
```

После этого аналогично смените пароли менеджера и инженера либо создайте отдельный механизм учётных записей перед расширением команды.

## Архитектура

```text
Browser
  ↓
Nginx / Web
  ↓ /api
Fastify API
  ↓
PostgreSQL
```

Frontend использует same-origin `/api/v1`, поэтому отдельный публичный порт backend в штатной работе не требуется.

## Резервное копирование

Создать backup:

```bash
sh scripts/backup.sh
```

Файлы сохраняются в локальную папку `backups/`.

Восстановление:

```bash
sh scripts/restore.sh backups/profi24_YYYYMMDD_HHMMSS.dump
```

Для реальной эксплуатации настройте ежедневный backup по cron и копирование резервной копии на отдельное хранилище.

## Обновление

```bash
git pull
docker compose up -d --build
```

При запуске API автоматически выполняются безопасные `ADD COLUMN IF NOT EXISTS`/`CREATE TABLE IF NOT EXISTS` миграции.

## Основной workflow заявки

```text
NEW
→ ASSIGNED
→ ACCEPTED
→ DIAGNOSTICS
→ APPROVAL_REQUIRED
→ WAITING_PART / REPAIR
→ TESTING
→ PAYMENT_REQUIRED
→ CLOSED
```

Заявка не закрывается при неполной оплате.

После полной оплаты автоматически создаётся задача на контроль качества через 24 часа.

## Финансовая модель

Для заявки рассчитывается:

```text
Gross Profit = Total - Direct Cost
Gross Margin = Gross Profit / Total × 100%
```

Dashboard показывает выручку, прямые затраты, валовую прибыль, полученную оплату и дебиторку.

## Рекламации

Рекламация связывается с исходной заявкой и классифицируется по G1–G8. Для G4/G5 система автоматически создаёт Quality Incident, если открытого инцидента ещё нет.

## Что ещё нужно перед большим масштабированием

Текущая версия уже пригодна для пилотной эксплуатации внутри сервисного центра, но перед массовым запуском филиалов нужно добавить: полноценное управление пользователями и правами, файловое/object storage для фото, склад с остатками и движениями, автоматический ФОТ/KPI, B2B-договоры, WhatsApp/телефонию, мониторинг ошибок и внешнее off-site резервное копирование.
